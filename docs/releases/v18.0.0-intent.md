# Release intent — v18.0.0

## What this release is about

This release introduces semantic token integration and component variable exports for Cedar. Components now consume semantic token contracts directly from `@rei/cdr-tokens`, enabling theming-driven token overrides without CSS custom property hacks. The checkbox component aligns with Figma-confirmed state matrix. SCSS utility mixins remain in `@rei/cdr-tokens` (deprecation reversal from alpha.5 to alpha.6).

## What consumers will care about most

- **Semantic token overrides:** teams can now theme Cedar components using semantic token contracts (`--cdr-intents-*`) instead of CSS custom property hacks. Before this release, theming required deep knowledge of internal CSS variable names. Now semantic intent tokens like `--cdr-intents-text-primary` provide clear, documented theming points.

- **Component variable exports:** all Cedar components now export their CSS custom properties as a generated JSON map and SCSS mixin. Before this release, component variables were scattered across individual files or not available at all. Now teams can import `@rei/cedar/component-variables` to get a complete map of all component tokens.

- **Checkbox Figma alignment:** the checkbox component now matches the Figma-confirmed state matrix for all interaction states. Before this release, some visual states did not match the design tool.

- **SCSS utility mixins remain in @rei/cdr-tokens:** the deprecation from alpha.5 was reversed in alpha.6. Mixins (breakpoint, display, typography) continue to ship from the token package. No migration required.

## What changed internally that should NOT appear in release notes

- Build tooling changes (pnpm, Vite, etc.)

- Cedar-ops backlog candidates
- Storybook navigation and naming fixes
- v-html safety comments

- Component variable generation refactoring

## Known breaking changes

- Requires `@rei/cdr-tokens` >=15.0.0-alpha.6 for semantic token contracts
- Component variable export paths may have changed (check migration guide)

## Cross-repo notes

Cedar v18 depends on `@rei/cdr-tokens` 15.0.0.0-alpha.6 for semantic token contracts and SCSS utility mixins.

## BOLO — things consumers should watch for

- Semantic token contract names may differ from previous internal CSS variable names
- Component variable JSON export structure should be verified before adoption

## Success criteria

- Teams can theme components using semantic token contracts
- Component variable exports are consumed successfully
- Checkbox visual states match Figma
- No build failures related to token package upgrade
