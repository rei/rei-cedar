# Release notes – v18.0.0

## Overview

Teams can now theme Cedar components using semantic token contracts (`--cdr-intents-*`) instead of CSS custom property hacks. All Cedar components export their CSS custom properties as a generated JSON map and SCSS mixin, enabling programmatic token inspection and theming. The checkbox component now aligns with the Figma-confirmed state matrix for all interaction states. SCSS utility mixins (breakpoint, display, typography) remain in `@rei/cdr-tokens` — the deprecation from alpha.5 was reversed in alpha.6. **Upgrade together with `@rei/cdr-tokens` 15.0.0.0-alpha.6 or later.**

<details>
<summary>## Migration guide

### Must update

Required breaking changes that must be addressed to continue using this version.

- [ ] **Upgrade `@rei/cdr-tokens` to 15.0.0.0-alpha.6 or later** — Cedar v18 requires semantic token contracts and SCSS utility mixins from the token package:

  ```
  npm install @rei/cdr-tokens@15.0.0.0-alpha.6
  ```

- [ ] **Replace CSS custom property hacks with semantic token overrides** (if theming Cedar components):

  ```diff
  - .my-component {
  -   --cdr-color-text-primary: custom-color;
  - }
  + .my-component {
  +   --cdr-intents-text-primary: custom-color;
  + }
  ```

  Semantic token contracts provide clear, documented theming points. See the [Semantic Token Consumer Contract](?path=/docs/consumer-contract-semantic-tokens--docs) for available contracts.

- [ ] **Update component variable import paths** (if consuming component variables):

  ```diff
  - import componentVariables from '@rei/cedar/dist/component-variables.json'
  + import componentVariables from '@rei/cdr-tokens/component-variables'
  ```

  Component variables are now exported from the token package for consistency.

### Optional update

Recommended improvements to get the most out of this update.

- [ ] **Adopt component variable SCSS mixins** for programmatic token inspection:

  ```scss
  @use '@rei/cdr-tokens/component-variables' as vars;

  .my-component {
    @include vars.cdr-button;
  }
  ```

- [ ] Review semantic token contracts for theming opportunities
- [ ] Run your test suite to confirm compatibility

### To get the most out of this update

- Theme components using semantic token contracts with clear intent-based naming
- Access all component CSS custom properties via generated JSON export
- Use component variable SCSS mixins for programmatic token inspection
- Checkbox component now matches Figma-confirmed state matrix

<summary>## New features</summary>

- **Semantic token contracts for theming** — teams can now override component appearance using semantic intent tokens like `--cdr-intents-text-primary` instead of internal CSS variable names. Before this release, theming required deep knowledge of Cedar's internal CSS variable structure or brittle CSS custom property hacks. Now semantic token contracts provide clear, documented theming points that map to design intent.
  **Business value:** Easier theming, clearer documentation, reduced support burden, better alignment with design tools.
  To get started: use `--cdr-intents-text-primary` instead of `--cdr-color-text-primary` in your overrides

- **Component variable JSON export** — all Cedar components now export their CSS custom properties as a generated JSON map available from `@rei/cdr-tokens/component-variables`. Before this release, component variables were scattered across individual files or not available as a complete map. Now teams can programmatically inspect all component tokens in one place.
  **Business value:** Programmatic token inspection, better tooling support, easier design system integration.
  To get started: `import componentVariables from '@rei/cdr-tokens/component-variables'`

- **Component variable SCSS mixins** — every Cedar component now exports a SCSS mixin that includes all its CSS custom properties. Before this release, there was no way to programmatically include component variables in SCSS. Now teams can use `@include vars.cdr-button` to apply all button variables at once.
  **Business value:** Cleaner SCSS code, programmatic token application, better developer experience.
  To get started: `@use '@rei/cdr-tokens/component-variables' as vars; @include vars.cdr-button;`

- **Checkbox Figma alignment** — the checkbox component now matches the Figma-confirmed state matrix for all interaction states. Before this release, some visual states did not match the design tool. Now the component is visually consistent with Figma.
  **Business value:** Design fidelity, reduced handoff friction, better trust in design system.

</details>

<details>
<summary>## Breaking changes

- **Requires `@rei/cdr-tokens` 15.0.0.0-alpha.6 or later** — Cedar v18 consumes semantic token contracts and SCSS utility mixins from the token package
  - **Why:** Cedar's semantic token integration depends on the token package's contract layer and utility mixins
  - **Before:** Cedar v17 worked with `@rei/cdr-tokens` v14
  - **After:** Cedar v18 requires `@rei/cdr-tokens` 15.0.0.0-alpha.6 or later
  - **Migrate:** upgrade `@rei/cdr-tokens` to 15.0.0.0-alpha.6 or later. A consuming app that upgrades Cedar without upgrading tokens will fail at build time

- **Component variable export moved to token package** — component variables are now exported from `@rei/cdr-tokens/component-variables` instead of Cedar
  - **Why:** Centralizes token exports in the token package for consistency
  - **Before:** Component variables were exported from `@rei/cedar/dist/component-variables.json`
  - **After:** Component variables are exported from `@rei/cdr-tokens/component-variables`
  - **Migrate:** update import path to `@rei/cdr-tokens/component-variables`

### Component API changes

- **No component props, slots, or events changed** — this release focuses on token integration and exports, not component APIs

</details>
